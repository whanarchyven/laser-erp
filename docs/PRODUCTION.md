# Развёртывание: сервер и четыре станка

Веб и база стоят на одном сервере. На каждом компьютере станка ставится агент: он забирает задачу, кладёт файл `.lxds` в `C:\Jobs` и открывает его в CypCut. «Старт», лист и рамку нажимает оператор на станке, как сейчас. Агент станок не двигает.

Другая система ходит на тот же сервер по HTTP, веб при этом остаётся. Контракт: [API.md](API.md).

## Что уже можно разворачивать

- Сервер одной командой, страница «Очередь станка», вкладки **Очередь**, **Новая задача**, **Станки**, **Номенклатура**.
- Агент 0.8.0: сеть, установка, пульс раз в 5 секунд, открытие файла в CypCut, снимок окна, журнал. Конец листа ищется по строкам «Конец обработки», «Processing End», «Production ends», «加工结束».
- Внешний API на порту 3211, список методов совпадает с кодом.

Чего на настоящем станке ещё не было: полного цикла «Старт → конец листа → деталь засчитана» на вашей русской версии CypCut. Если строка конца в журнале другая, лист в вебе не прибавится сам. На странице задачи есть кнопка **Лист вырезан**.

Агент в git не лежит. Перед выездом его нужно собрать (шаг 0).

## Кто где

| | Адрес | Что запущено |
|---|---|---|
| Сервер, карта в коммутатор станков | 192.168.50.1 | `Запустить-сервер.cmd`: база, API, веб |
| Сервер, вторая карта | адрес офиса, как сейчас | интернет только на время установки Docker |
| Лазер-1 … Лазер-4 | 192.168.50.2 … .5 | Windows с входом пользователя, CypCut, агент |
| Коммутатор станков | — | в интернет и в офисный роутер не включать |

Маска везде `255.255.255.0`. На карте станков и на станках шлюз и DNS пустые. Иначе компьютер начнёт искать интернет через сеть, где его нет.

Страница для людей: `http://192.168.50.1:5173`.

Для другой программы: `http://192.168.50.1:3211`, заголовок `Authorization: Bearer <API_TOKEN>`. Загрузка файла ещё использует порт 3210.

## 0. Сегодня, на компьютере с интернетом

1. Поставить Docker Desktop и дождаться «Engine running». Поставить Node.js 20 и Git.
2. `git clone https://github.com/whanarchyven/laser-erp.git`, в папке `npm install`.
3. Собрать флешку, если папки ещё нет. На компьютере, где готовился этот текст, она уже собрана: `laser-erp\agent\usb\LaserAgent`. Заново:

   ```bat
   powershell -NoProfile -ExecutionPolicy Bypass -File agent\build-usb.ps1
   ```

   Получится `agent\usb\LaserAgent`. Эту папку целиком скопировать на флешку. Одной флешки хватает на все четыре станка.
4. На сервере назначить карте станков `192.168.50.1` без шлюза. Вторую карту не трогать.
5. Первый запуск, пока есть интернет (качаются образы Docker):

   ```bat
   set SERVER_IP=192.168.50.1
   Запустить-сервер.cmd
   ```

   В конце строка «BaseUrl агента» должна быть `http://192.168.50.1:3211`. Если там другой адрес, `server\.env` уже успел создаться не тем: остановить командой из окна скрипта, в `server\.env` поправить `CONVEX_CLOUD_ORIGIN` и `CONVEX_SITE_ORIGIN` на `192.168.50.1`, запустить скрипт снова.
6. Браузер: `http://192.168.50.1:5173`, видна «Очередь станка».
7. Ключи из того же окна записать. Пока оба `laser-stand-dev`. Сеть станков без интернета, для завтра этого достаточно. Если порт 3211 виден из офиса, в `server\.env` заменить `AGENT_TOKEN` и `API_TOKEN` на свои длинные строки и запустить скрипт ещё раз. `INSTANCE_SECRET` не менять.

Повторный запуск скрипта задачи не стирает. Остановка без потери данных: `docker compose -f server\docker-compose.yml down`. С ключом `-v` база сотрётся.

## 1. Завтра: сервер

1. Docker Desktop запущен.
2. Карта станков по-прежнему `192.168.50.1` без шлюза.
3. В папке проекта:

   ```bat
   set SERVER_IP=192.168.50.1
   Запустить-сервер.cmd
   ```

4. С самого сервера открывается `http://192.168.50.1:5173`.
5. Проверка API, в командной строке, ключ из `server\.env`:

   ```bat
   curl -H "Authorization: Bearer laser-stand-dev" http://192.168.50.1:3211/api
   ```

   Ответ `200` и список методов. Без ключа будет `401`.

Окно скрипта после «Готово» можно закрыть: сервер работает в Docker. Автозапуск Docker включить, чтобы после перезагрузки сервера очередь поднялась сама.

## 2. Четыре станка

На каждом компьютере: Windows 10 или 11, 64 бита, уже стоит CypCut, есть пароль администратора. Ставить по одному. Установщик предлагает первый свободный адрес, начиная с `.2`. Если запустить два установщика сразу, оба могут предложить один и тот же.

| Порядок | Имя в вебе | Адрес, если предложенный устраивает |
|---|---|---|
| 1 | Лазер-1 | 192.168.50.2 |
| 2 | Лазер-2 | 192.168.50.3 |
| 3 | Лазер-3 | 192.168.50.4 |
| 4 | Лазер-4 | 192.168.50.5 |

На станке:

1. Кабель из сетевой карты компьютера станка в коммутатор станков. Если эта карта сейчас сидит в цеховой сети со шлюзом, не перенастраивать её: воткнуть USB-карту и выбирать её в установщике.
2. Войти в Windows. Агент запускается при входе пользователя и открывает CypCut в этом сеансе. Экран можно заблокировать, выходить из системы нельзя.
3. Флешка → **Установить.cmd** → да на запрос администратора.
4. Ответы:

   | Вопрос | Что ввести |
   |---|---|
   | IP-адрес сервера | 192.168.50.1 |
   | Номер адаптера | тот, где кабель в коммутатор станков. Если скрипт пишет «шлюз» и спрашивает «Продолжить?», ответить «нет» и выбрать другую карту |
   | IP-адрес этого станка | Enter, если в скобках `.2`, `.3`, `.4` или `.5` по таблице |
   | Ключ агента | тот, что напечатал сервер |
   | Имя станка | `Лазер-1`, на следующем станке другое имя. По нему задача выбирает станок |
   | Путь к CypCut | Enter, если скрипт сам его нашёл |

5. В конце «Сервер отвечает (200)» и «Готово».
6. На сервере вкладка **Станки**. Карточка с этим именем, IP, «агент 0.8.0», без строки «нет связи больше минуты». Когда CypCut открыт, бейдж «CypCut запущен» и снимок окна.

Со станка: `ping 192.168.50.1` отвечает. `ping 8.8.8.8` не отвечает. В браузере станка открывается `http://192.168.50.1:5173`.

Повторный `Установить.cmd` обновляет агента и сохраняет имя. Снять агента: **Удалить.cmd** с той же флешки. Журнал: `C:\Jobs\agent.log`. Настройки: `C:\Program Files\LaserAgent\appsettings.json`.

## 3. Первая задача через веб

Когда на **Станках** видны все четыре карточки:

1. **Новая задача**.
2. Список **Станок** — `Лазер-1`.
3. «Выберите файл .lxds» — раскрой, не плоский чертёж. Появятся картинки листов.
4. Толщина, например `1.0`. В CypCut листы будут называться «Лист 1 (1.0мм)», «Лист 2 (1.0мм)».
5. У деталей без карточки заполнить наименование и артикул.
6. **Сохранить и в очередь**.

На **Очереди** у Лазера-1 задача проходит «в очереди» → «файл на станке» → «открыт в CypCut». На компьютере станка CypCut сам откроет этот файл. Дальше оператор кладёт лист, выбирает лист в списке слева, при необходимости жмёт «Рамка» и «Старт».

После конца листа задача показывает вырезанный лист, а количества деталей растут по составу листа. Когда вырезаны все, задача закрывается, агент открывает следующую для этого станка.

Если лист вырезан, а веб молчит: открыть задачу и нажать **Лист вырезан**. Строка журнала CypCut, которая при этом была на экране, пригодится, чтобы добавить её в распознавание.

Задачу на другой станок ставят тем же экраном: в списке **Станок** выбрать `Лазер-2`.

## 4. Другая система

Веб не выключать. Программа ходит рядом:

| | |
|---|---|
| Методы | `http://192.168.50.1:3211` |
| Ключ | `API_TOKEN` из `server\.env`, заголовок `Authorization: Bearer …` |
| Файл | сначала `POST /api/files/upload-url` на 3211, потом байты на адрес с портом 3210 |
| Контракт | [API.md](API.md) |

Проверка связи: `GET /api` с ключом возвращает список методов.

Короткий путь поставить задачу: `GET /api/machines` → загрузить `.lxds` → `POST /api/presets/inspect` → `POST /api/presets` с `"enqueue": true` и `"machineId": "Лазер-1"`. Статус смотреть через `GET /api/jobs?jobId=`.

## Если на экране не то

| Что видно | Куда смотреть |
|---|---|
| «Веб» в окне скрипта не `192.168.50.1` | `server\.env`, оба `CONVEX_*_ORIGIN`, запустить скрипт снова |
| Страница с сервера открывается, со станка нет | кабель, адрес станка, брандмауэр сервера. Правило «Laser ERP server» должно разрешать 3210, 3211, 5173 |
| Установщик: «Сервер отклонил ключ» | ключ не совпал с `AGENT_TOKEN` |
| Карточка есть, но «нет связи больше минуты» | на станке вышли из Windows или агент не запущен. Войти в систему. Журнал `C:\Jobs\agent.log` |
| В списке **Станок** пусто | ни один агент ещё не прислал пульс. Сначала шаг 2 |
| Задача остаётся «в очереди» | на карточке станка текст ошибки. Часто не найден `CypCut.exe` или нет входа в Windows |
| Файл открылся, лист не засчитан | в журнале CypCut другая фраза конца. Нажать **Лист вырезан** и сохранить эту строку |
| Два станка получили один адрес | ставить по одному. Адрес правится повторным `Установить.cmd` |
