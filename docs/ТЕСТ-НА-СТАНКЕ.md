# Тест на реальном станке — пошагово

Документ для первого прогона системы на настоящем лазере: ноутбук мастера (сервер и веб) + компьютер станка с CypCut (агент).
Идите по шагам сверху вниз, ставьте галочки. Всё, что пошло не так, записывайте в «Журнал теста» в конце — с временем.

> **Безопасность.** Агент станок не трогает: он не нажимает «Старт», не двигает головку и не меняет параметры резки.
> Он только скачивает файл, открывает его в CypCut и читает, что CypCut показывает и пишет в журнал.
> Всё физическое — лист, рамку, «Старт», аварийный стоп — делает оператор, как обычно. Правила безопасности цеха действуют без изменений.

---

## 0. Что взять с собой

**Железо**
- [ ] Ноутбук с проектом `laser-erp` (на нём сервер и веб).
- [ ] Зарядка для ноутбука — сервер должен работать весь тест.
- [ ] Патч-корд (обычный сетевой кабель RJ-45), 3–5 м. Подойдёт любой: современные сетевые карты сами разбираются с «прямым/перекрёстным».
- [ ] USB-сетевая карта (на всякий случай: если единственный сетевой порт станка занят цеховой сетью).
- [ ] Флешка с папкой `agent\usb\LaserAgent` (см. шаг 1.3).
- [ ] Телефон — фотографировать экран CypCut и журнал при странностях.

**Файлы**
- [ ] 1–2 настоящих файла `.lxds` **с раскроем** (из папки «Варианты»: там есть список листов и состав деталей). Лучше один простой — 2–3 листа, и один, где у листа количество больше 1 (×2, ×3).
- [ ] Материал под эти раскрои на станке (или договоритесь резать на обрезках / в «сухую» без луча, если так можно на вашем станке).

**Что узнать у хозяина станка заранее**
- [ ] Версия Windows на компьютере станка: нужна **Windows 10 или 11, 64-бит**. На Windows 7 и на 32-битной Windows агент не запустится (Пуск → Параметры → Система → О системе → «Тип системы»).
- [ ] Есть ли свободный сетевой порт или он занят цеховой сетью.

**Доступы**
- [ ] Пароль администратора Windows на компьютере станка (установщик и настройка сети просят права администратора).
- [ ] Согласие хозяина станка, что на его компьютер ставится фоновая программа и меняется адрес сетевого порта.

## 1. Подготовка ноутбука (дома / до выезда)

### 1.0. Если ноутбук чистый (ничего не установлено)
Делается один раз, **дома, с интернетом**. Если на ноутбуке сервер уже запускался — пропустить.

1. [ ] Установить **Node.js LTS**: с сайта nodejs.org (установщик Windows, всё по умолчанию) или в PowerShell:
   ```powershell
   winget install OpenJS.NodeJS.LTS
   ```
   Открыть **новое** окно PowerShell и проверить: `node -v` и `npm -v` печатают версии.
2. [ ] Получить проект `laser-erp`:
   - с GitHub: `git clone git@github.com:whanarchyven/laser-erp.git` (нужен Git: `winget install Git.Git`), **или**
   - скопировать папку проекта с другого компьютера **без** папок `node_modules` и `.convex` (они создадутся сами).
3. [ ] В папке проекта:
   ```powershell
   npm install
   ```
4. [ ] Запустить **`Запустить-сервер.cmd`**. При первом запуске Convex сам скачает локальный сервер и создаст файл `.env.local` — это 1–3 минуты. Ждать, пока в окне **Convex** появится `Convex functions ready!`.
   Если окно Convex задаёт вопросы — отвечать по умолчанию (Enter).
5. [ ] Задать ключ агента (без него сервер отклоняет любого агента: «Сервер отклонил ключ агента»). В папке проекта:
   ```powershell
   npx convex env set AGENT_TOKEN laser-stand-dev
   ```
   Ключ должен совпадать с `Token` в `laser-agent.json` на флешке.
6. [ ] Открыть `http://localhost:5173` — видна страница «Очередь станка».
7. [ ] **Флешка.** Собранный агент в git не хранится. Проще всего взять готовую флешку, собранную на основном ноутбуке. Собрать на этом можно только с установленным .NET 8 SDK (`winget install Microsoft.DotNet.SDK.8`), см. 1.3.

База на новом ноутбуке пустая — это нормально. Папку `.convex` с другого компьютера переносить не нужно.

### 1.1. Сервер запускается
- [ ] Открыть папку проекта, запустить **`Запустить-сервер.cmd`**.
- [ ] Должны открыться два окна: **Convex** и **Web**. Не закрывать их до конца теста.
- [ ] В окне скрипта будет список адресов ноутбука с подсказками «веб: …:5173» и «BaseUrl агента: …:3211».
- [ ] Открыть в браузере `http://localhost:5173` — видна страница «Очередь станка».

### 1.1.1. Репетиция без интернета (обязательно)
У станка интернета, скорее всего, не будет. Проверить дома:
- [ ] Закрыть окна Convex и Web.
- [ ] Отключить Wi-Fi и вытащить сетевой кабель интернета.
- [ ] Снова запустить `Запустить-сервер.cmd`, дождаться `Convex functions ready!`.
- [ ] Открыть `http://localhost:5173`, зайти в «Новая задача», загрузить `.lxds` — видны картинки листов.
- [ ] Если без интернета сервер **не стартует** — у станка запускать его заранее, пока интернет есть, и не закрывать окна. В настройках питания ноутбука отключить сон и гибернацию на время теста.

### 1.2. Чистые данные (по желанию)
Если нужно начать с нуля (как для нового станка) — в папке проекта в терминале повторять, пока не напишет `0`:
```powershell
npx convex run wipe:batch
```
Удаляет все задачи, пресеты, номенклатуру, станки и файлы. Ключ агента (`AGENT_TOKEN`) не трогается.

### 1.3. Флешка с агентом
- [ ] Собрать свежий агент (если менялся код; нужен .NET 8 SDK — в папке `agent\.tools\dotnet` или установленный в системе):
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File agent\build-usb.ps1
  ```
- [ ] Скопировать **всю папку** `agent\usb\LaserAgent` на флешку.
- [ ] Открыть на флешке `laser-agent.json` и проверить:
  - `BaseUrl` = `http://192.168.50.1:3211` (адрес ноутбука по прямому кабелю);
  - `Token` = тот же ключ, что на сервере (для текущего стенда `laser-stand-dev`);
  - `MachineId` пустой — установщик спросит имя.
- [ ] Сверить размер `LaserAgent.exe` на флешке и в `agent\usb\LaserAgent` — должен совпадать до байта (было, что файл копировался обрезанным и агент не запускался).

### 1.4. Пресет заранее (экономит время у станка)
Можно сделать дома, пока станка нет: станок для пресета не нужен.
- [ ] «Новая задача» → «Новый пресет из LXDS» → выбрать `.lxds`.
- [ ] Проверить, что видны **картинки листов** и под каждым «рез … м · пробивок …».
- [ ] Проверить, что в таблице у каждой детали есть **чертёж** (колонка «Картинка»).
- [ ] Для каждой детали без карточки заполнить «Наименование» и «Артикул» (описание — по желанию). При желании — «загрузить фото» вместо чертежа.
- [ ] Нажать **«Сохранить пресет»** (не «в очередь» — станка ещё нет).
- [ ] «Номенклатура» — появились карточки с картинками.

## 2. Физическое подключение у станка

1. [ ] Убедиться, что станок в обычном рабочем состоянии, CypCut открывается, оператор рядом.
2. [ ] Посмотреть, есть ли у компьютера станка свободный сетевой порт.
   - Если единственный порт занят цеховой сетью/интернетом — **не выдёргивать** его без согласования. Воткнуть USB-сетевую карту и работать через неё.
   - Если ноутбук и станок уже в одной цеховой сети — кабель не нужен, шаг 3 пропустить, в `BaseUrl` указать цеховой адрес ноутбука (его покажет `Запустить-сервер.cmd`).
3. [ ] Соединить ноутбук и станок патч-кордом. Индикаторы на портах должны загореться.

---

## 3. Сеть (только для прямого кабеля)

### 3.1. Ноутбук
- [ ] На ноутбуке запустить `agent\installer\Настроить-сеть.cmd` (или с флешки), подтвердить права администратора.
- [ ] Выбрать номер адаптера, **куда воткнут кабель** (в списке видно «состояние=Up»).
- [ ] Адрес: **`192.168.50.1`**.
- [ ] Если скрипт предупреждает «адаптер подключён к сети со шлюзом» — это значит, вы выбрали адаптер с интернетом. Ответить «нет» и выбрать другой.

### 3.2. Станок
- [ ] С флешки запустить `Настроить-сеть.cmd`, адрес **`192.168.50.2`** (второй станок — `.3` и т.д.).
- [ ] То же предупреждение про шлюз → «нет», взять USB-сетевую карту.

### 3.3. Проверка связи
- [ ] На станке в PowerShell: `ping 192.168.50.1` — ответы есть.
- [ ] На станке в браузере: `http://192.168.50.1:5173` — открывается веб. Если ping есть, а веб нет — брандмауэр ноутбука: перезапустить `Запустить-сервер.cmd` и согласиться на права администратора (он открывает порты 3210, 3211, 5173).

## 4. Установка агента на станок

1. [ ] С флешки запустить **`Установить.cmd`**, подтвердить права администратора.
2. [ ] Ответы на вопросы (Enter оставляет значение в скобках):
   - «Адрес сервера» — `http://192.168.50.1:3211`;
   - «Ключ агента» — как в `laser-agent.json`;
   - «Имя станка» — своё, понятное, например `Лазер-1`. Так станок будет называться в вебе.
3. [ ] Установщик сам находит CypCut. Если не нашёл — указать путь к `CypCut.exe`.
4. [ ] В конце должно быть зелёным: **«Сервер отвечает (200)»** и **«Готово. Агент работает в фоне…»**.
   - «Сервер отклонил ключ агента» → неверный `Token`.
   - «Сервер недоступен» → вернуться к шагу 3.3.
   - «Агент установлен, но не запустился» → открыть `C:\Jobs\agent.log`, сфотографировать, см. раздел 9.
5. [ ] Если CypCut на станке ещё не открыт — открыть его как обычно.

### 4.1. Проверка в вебе (на ноутбуке)
- [ ] Страница **«Станки»**: появился ваш станок, «агент 0.7.0», «CypCut запущен», состояние станка («Стоит» / «Режет» / «Обход рамки»), связь — текущее время.
- [ ] Через 15–30 секунд появился **снимок окна CypCut**. Он похож на то, что на экране станка.
- [ ] Видны «Значения на панели CypCut» и «Журнал CypCut (последние строки)».
- [ ] Записать в журнал теста: **на каком языке** CypCut пишет журнал (русский / английский / китайский). Это важно для пунктов 6.4 и 6.5.

## 5. Постановка задачи

1. [ ] На ноутбуке: «Новая задача» → в поле «Станок» выбрать ваш станок.
2. [ ] В «Из сохранённого пресета» у нужного пресета нажать **«В очередь»** (или загрузить `.lxds` прямо сейчас и нажать «Сохранить и в очередь»).
3. [ ] Откроется страница задачи `J-1`. Статус по шагам:
   - «в очереди» → «доставлено» (агент скачал файл в `C:\Jobs`, до 5–10 секунд);
   - → «загружено» (агент открыл файл в CypCut).
4. [ ] На станке CypCut сам открыл файл задачи — в заголовке окна имя `J-1_….lxds`.
   - Если в CypCut был открыт другой несохранённый чертёж, CypCut спросит про сохранение — ответить самим. Агент ждёт.
   - Если за минуту файл не открылся — открыть вручную из `C:\Jobs` и записать в журнал теста.
5. [ ] На странице задачи блок **«Листы раскроя»**: картинки совпадают с тем, что в CypCut слева в списке «Nest result 1, 2, …».

## 6. Резка — главная часть

Для **каждого** листа повторять 6.1–6.4. Оператор делает всё как обычно, вы смотрите в веб.

### 6.1. Выбор листа
- [ ] Оператор в CypCut **в списке слева кликает нужный лист** («Nest result N»), кладёт лист металла, при необходимости «Рамка».
- [ ] В вебе на странице задачи этот лист обведён рамкой с подписью **«выбран в CypCut»** (до 5–10 секунд). Над листами — «Рамкой отмечен лист, выбранный сейчас в CypCut».
- [ ] На «Станки» — «Выбран в CypCut: N».

### 6.2. Старт
- [ ] Оператор жмёт **«Старт»**.
- [ ] Статус задачи стал **«режется»**.
- [ ] На странице задачи появилась строка **«Последний старт в CypCut (лист N): оценка CypCut ≈ …, рез … м, холостые … м, пробивок …»**.
- [ ] У карточки этого листа — та же «оценка CypCut ≈ …». Рядом «наша оценка ≈ …» — сравнить, записать обе в журнал теста.

### 6.3. Окончание
- [ ] CypCut закончил лист (в журнале CypCut «Processing End» / «Production ends» / «Конец обработки»).
- [ ] В вебе в течение 10 секунд:
  - «Листов вырезано: 1 из N», полоса прогресса сдвинулась;
  - у карточки листа «вырезано 1 из 1», «в CypCut: вырезан», **«факт: m:ss»**;
  - в таблице деталей у деталей с этого листа выросло «Готово».
- [ ] Сверить «факт» с секундомером / с «Spend time» в журнале CypCut. Записать.

### 6.3.1. Авария и остановка посреди листа
- [ ] Если CypCut пишет `Alarm:…` — на «Станки» красная строка «Авария: …», бейдж состояния красный. После `Alarm Remove:…` строка пропадает.
- [ ] Если лист остановлен (`Working --> Stop`) без «Production ends» — в «События станка» запись «остановлен до конца листа» с текстом аварии (или «Остановлено оператором»). Лист **не** засчитывается; после перезапуска и «Production ends» засчитывается один раз.

### 6.4. Проверка учёта деталей
- [ ] Открыть картинку листа и **пересчитать детали на нём руками** по позициям. Совпадает с тем, насколько выросло «Готово»?

### 6.5. Обязательные нестандартные случаи
Сделать хотя бы по одному разу, каждый записать в журнал теста:
- [ ] **Не по порядку.** Вырезать, например, лист 3 раньше листа 2. В вебе засчитаться должен именно лист 3.
- [ ] **Лист ×2 / ×3** (если есть в файле). В CypCut у такого листа «Done: 1/2». Проверить, что каждый проход засчитывается и что веб пишет «вырезано 1 из 2».
- [ ] **Стоп посередине.** Нажать «Стоп» во время резки (на безопасном месте, по решению оператора). Записать: засчитал ли веб лист (не должен, но это **главный неизвестный момент** — CypCut может писать «конец обработки» и при стопе). Сфотографировать журнал CypCut.
- [ ] **Пауза → продолжить.** Не должно засчитывать лист дважды.
- [ ] **Повтор того же листа** (перерез брака). Записать, что сделал веб (лишний проход сверх плана не засчитывается — это ожидаемо).
- [ ] **Обрыв сети.** Во время резки вытащить кабель, дождаться конца листа, воткнуть обратно. Через 10–20 секунд после восстановления лист должен засчитаться (агент копит события и досылает).
- [ ] **Ручная отметка.** Если отметка не пришла сама — кнопка «Лист вырезан» на странице задачи. Проверить, что она работает.

### 6.6. Конец задачи
- [ ] После последнего листа задача сама стала «выполнено».
- [ ] Если в очереди есть следующая задача — агент сам открыл её в CypCut.

## 7. Служебные проверки (после резки)

- [ ] **Отмена.** Поставить ещё одну задачу и нажать «Отменить» → файл пропал из `C:\Jobs` (до 10 секунд).
- [ ] **Перезагрузка компьютера станка** (если разрешат): после входа в Windows агент запустился сам — на «Станки» связь снова свежая.
- [ ] **CypCut закрыт.** Закрыть CypCut, поставить задачу → агент сам запустил CypCut с файлом.

---

## 8. Сбор материалов (до отъезда!)

С компьютера станка скопировать на флешку:
- [ ] `C:\Jobs\agent.log` — журнал агента;
- [ ] `C:\Jobs\cypcut-windows.txt` — что агент видит в окнах CypCut (в конце строка `nest current=… done=…`);
- [ ] `C:\Jobs\cypcut.bmp` — последний снимок окна;
- [ ] фото экрана CypCut с журналом после старта и после конца листа (особенно если CypCut на русском — нужны точные фразы «длина реза», «общее время» и т.п.).

С ноутбука:
- [ ] скриншоты страницы задачи и «Станки».

## 9. Если что-то не работает

| Симптом | Что смотреть |
|---|---|
| Станка нет на «Станки» | `C:\Jobs\agent.log`. Есть ли строка «Агент 0.7.0 … → http://192.168.50.1:3211». Ошибки `401` — ключ, ошибки соединения — сеть (шаг 3.3). |
| «Агент установлен, но не запустился» | Журнал событий Windows → «Приложение», источник `.NET Runtime`. Сообщение «possible file corruption» = `LaserAgent.exe` скопирован не полностью — скопировать заново и сверить размер. |
| Задача висит «в очереди» | Агент не видит задачу: имя станка в задаче и в агенте должно совпадать. |
| Висит «доставлено», CypCut не открыл файл | Открыто окно CypCut с вопросом (сохранить? лицензия?) — ответить. Иначе открыть файл вручную из `C:\Jobs`. |
| Лист не засчитался после конца | Журнал CypCut пишет конец не теми словами. Сфотографировать журнал → дописать фразу в `FinishPatterns` в `C:\Program Files\LaserAgent\appsettings.json`, затем в Диспетчере задач завершить `LaserAgent` и запустить заново через «Установить.cmd» (сохранит настройки). Пока — кнопка «Лист вырезан». |
| Нет «оценки CypCut» после старта | CypCut пишет оценку на другом языке. Сфотографировать журнал — поддержку добавим. |
| «Выбран в CypCut» не показывается | Открыта не вкладка списка листов («Nesting») слева, а «Parts»/«Plates». Переключить. Если всё равно нет — `cypcut-windows.txt`, строки `TFsCheckListBox` и `item …`. |
| Красная плашка «В CypCut отмечены вырезанными листы …, а у нас учтены …» | Учёт разошёлся с CypCut (например, лист вырезали без агента). Записать, какие листы реально вырезаны. |

**Не создавать** на станке файл `C:\Jobs\diag.txt` — это отладочная команда, по ней агент кликает в окне CypCut.
