# Задание сисадмину: сеть и сервер лазерных станков

Станки в интернет не ходят. Коммутатор, к которому они подключены, в интернет не выпускать: его MAC на выходе уже заблокирован, и поднимать ему интернет не нужно. Сервер стоит двумя ногами: одна в этой локальной сети, вторая в сеть с интернетом. Агенты на станках и приложение сами обращаются к серверу. Сервер на станки никуда не подключается.

## 1. Что получится

```
интернет / офис
        │
        │  только сервер, вторая сетевая карта
        │
   ┌────┴─────────┐
   │    сервер    │
   │  .50.1       ├──── коммутатор станков (в интернет не подключать)
   └──────────────┘         │
              ┌─────────────┼──────────────┐
           станок 1      станок 2     компьютер приложения
           .50.2         .50.3        .50.10
```

Адреса ниже — рабочие. Менять их можно, если вся таблица меняется одинаково.

| Узел | Куда воткнут | IP | Маска | Шлюз | DNS |
|---|---|---|---|---|---|
| Сервер, карта локальной сети | коммутатор станков | `192.168.50.1` | `255.255.255.0` | не задавать | не задавать |
| Сервер, карта офиса/интернета | офисная сеть | как выдаёт офис | как выдаёт офис | шлюз офиса | DNS офиса |
| Станок 1 | коммутатор станков | `192.168.50.2` | `255.255.255.0` | не задавать | не задавать |
| Станок 2 | коммутатор станков | `192.168.50.3` | `255.255.255.0` | не задавать | не задавать |
| Следующие станки | тот же коммутатор | `192.168.50.4`, `.5`, … | `255.255.255.0` | не задавать | не задавать |
| Компьютер приложения, если он в цеху | тот же коммутатор | `192.168.50.10` | `255.255.255.0` | не задавать | не задавать |

Коммутатор станков — обычный неуправляемый, без DHCP и без VLAN. Кабель вверх, в офисный роутер, не подключать. Иначе станки снова окажутся за заблокированным MAC.

Шлюз на локальных картах не прописывать. Иначе Windows начнёт слать наружу через сеть, у которой нет выхода.

## 2. Порты на сервере

Слушает только сервер. На станках входящие порты открывать не нужно: агент сам устанавливает соединение.

| Порт TCP | Кто ходит | Зачем | Куда открывать |
|---|---|---|---|
| 3211 | агенты, приложение, браузер | API агента и внешнее API | локальная сеть `192.168.50.0/24`. В офис — только если приложение сидит там |
| 3210 | приложение при загрузке файла, браузер при открытии картинок | приём файлов и раздача картинок | туда же, куда 3211 |
| 5173 | браузер оператора | веб-страница очереди | локальная сеть и компьютер мастера |
| 6791 | только сисадмин | служебная панель базы | localhost. В сеть не открывать |

Брандмауэр Windows скрипт запуска открывает все четыре порта правилом «Laser ERP server». На Linux то же делает установщик. Если перед сервером стоит отдельный межсетевой экран, разрешить входящие TCP 3210, 3211 и 5173 с `192.168.50.0/24`. Порт 6791 снаружи не разрешать.

На станках разрешить исходящие TCP на `192.168.50.1` порты 3210 и 3211. Входящих правил для агента не добавлять.

## 3. Сервер

Нужна машина с двумя сетевыми картами, Windows 10/11 или Linux. На время первой установки у второй карты должен быть интернет: скачиваются образы Docker.

Поставить:

- Docker Desktop на Windows или Docker Engine и Docker Compose на Linux. Запустить и дождаться, пока демон работает.
- Node.js LTS. Проверка в новом окне терминала: `node -v` и `npm -v` печатают версии.
- Git, если проект забирается с GitHub.

Сеть:

1. На карте, которая смотрит в коммутатор станков, задать вручную `192.168.50.1/24`. Шлюз и DNS оставить пустыми.
2. Вторую карту оставить в офисной сети, как она настроена сейчас. Интернет должен открываться именно с неё.

Код и запуск. На Windows в папке проекта:

```bat
git clone https://github.com/whanarchyven/laser-erp.git
cd laser-erp
npm install
```

Перед первым запуском ключи лучше сменить со стендовых. Если файла `server\.env` ещё нет, запустить `Запустить-сервер.cmd` один раз, он создаст файл и напечатает адреса. Остановить сервер командой, которую скрипт печатает внизу (`docker compose ... down`). Открыть `server\.env` и выставить:

```
CONVEX_CLOUD_ORIGIN=http://192.168.50.1:3210
CONVEX_SITE_ORIGIN=http://192.168.50.1:3211
AGENT_TOKEN=<длинный секрет агентов>
API_TOKEN=<длинный секрет приложения>
```

`INSTANCE_SECRET` не трогать. Адреса должны быть локальными `192.168.50.1`: по ним ходят и станки, и приложение. Скрипт при первом создании файла мог подставить офисный адрес сервера, его заменить.

Запустить снова `Запустить-сервер.cmd` и дождаться «Готово». На Linux то же самое: `bash server/start.sh`.

Проверка на самом сервере:

- `http://192.168.50.1:5173` открывает страницу «Очередь станка».
- `http://127.0.0.1:3210/version` отвечает.
- `curl -H "Authorization: Bearer <API_TOKEN>" http://192.168.50.1:3211/api` возвращает JSON со списком методов. Без ключа ответ `401`.

Сервер после этого можно не держать в открытом окне: он работает в Docker. Автозапуск Docker включить, чтобы после перезагрузки сервер поднялся сам. Повторный запуск `Запустить-сервер.cmd` обновляет код и не стирает задачи.

Остановка без потери данных: `docker compose -f server\docker-compose.yml down`. Данные лежат в томе Docker. Команда `down -v` данные сотрёт, её не использовать.

## 4. Станки

На каждом компьютере станка: Windows 10 или 11, 64 бита, установленный CypCut, пароль администратора. Входящий интернет станку не нужен.

1. Патч-корд из сетевой карты компьютера станка в коммутатор станков. Если единственная карта занята другой сетью, поставить USB-карту и работать через неё. Карту с цеховым интернетом не перенастраивать.
2. Скопировать на станок папку `agent\installer` из репозитория. В ней уже лежит `LaserAgent.exe`, SDK ставить не нужно.
3. Запустить `Установить.cmd` от администратора.
4. На вопрос «IP-адрес сервера» ответить `192.168.50.1`.
5. Если адреса у станка ещё нет, установщик предложит свободный: первому станку `192.168.50.2`, второму `192.168.50.3`. Enter принимает предложенный. Адаптер выбрать тот, где воткнут кабель в коммутатор станков. Если скрипт предупреждает про шлюз, ответить «нет» и выбрать другую карту.
6. «Ключ агента» — значение `AGENT_TOKEN` из `server\.env`.
7. «Имя станка» — своё и постоянное, например `Лазер-1`. Второе имя на другом станке. По этому имени приложение выбирает станок.
8. В конце должно быть «Сервер отвечает (200)» и «Готово».

Агент стартует сам при входе в Windows. Повторный `Установить.cmd` обновляет программу и сохраняет имя станка.

Проверка со станка:

```
ping 192.168.50.1
```

Ответы есть. В браузере станка открывается `http://192.168.50.1:5173`. На странице «Станки» виден этот станок, его IP и свежее время связи.

Журнал агента: `C:\Jobs\agent.log`. Настройки: `C:\Program Files\LaserAgent\appsettings.json`. Снятие агента: `Удалить.cmd` из той же папки.

## 5. Приложение

Приложение ходит на тот же адрес, что и агенты.

| | |
|---|---|
| Базовый адрес | `http://192.168.50.1:3211` |
| Заголовок | `Authorization: Bearer <API_TOKEN>` |
| Контракт | `docs/API.md` в репозитории |

Загрузка чертежа идёт в два шага: приложение сначала получает адрес у порта 3211, потом отправляет файл на порт 3210 того же сервера. Поэтому приложению нужны оба порта.

Если компьютер приложения стоит в цеху, воткнуть его в коммутатор станков и дать ему `192.168.50.10/24` без шлюза. Если он в офисе, проложить ему маршрут в сеть `192.168.50.0/24` через офисную карту сервера и открыть на ней входящие TCP 3210 и 3211 только с адресов приложения. Публиковать эти порты в интернет целиком не нужно: у приложения и так есть ход в локальную сеть.

## 6. Сдача

Считается сделанным, когда одновременно верно всё:

1. Со станка `ping 192.168.50.1` проходит, а `ping 8.8.8.8` со станка не проходит.
2. `http://192.168.50.1:5173` открывается со станка и с компьютера приложения.
3. `http://192.168.50.1:3211/api` с ключом `API_TOKEN` отдаёт список методов, без ключа отвечает `401`.
4. Каждый станок виден на странице «Станки» со своим IP, и время связи обновляется.
5. Порт 6791 с другого компьютера не открывается.
